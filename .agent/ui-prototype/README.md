# Marunage（マルナゲ） — 幹事エージェント UIプロトタイプ

既存の `src/` には触れず、`.agent/ui-prototype/` だけで動く静的プロトタイプです。ブラウザーで `index.html` を開けば動きます。ビルドもサーバーも要りません。

## 画面

- `index.html` — `/`。あなたが返事をする1件を、進行表ごと最初に置く。
- `session.html?id=ses_21&state=consent` — 会の詳細。`state` を `waiting` / `consent` / `superseded` / `owner` / `confirmed` に変えると5つの状態見本を切り替えられる。
- `register.html` — 会の登録。最初に形式（プラグイン）を選ぶ。
- `audit.html` — 実行記録。エージェントがしたことと、プログラムが拒否したことを並べる。
- `system.html` — トークン、状態の割り当て、部品見本。

## 最大にしたもの

- `/`：会の一覧ではなく、あなたが返事をする1件の進行表。何がどう変わるかを詳細画面の前に読める。
- 会の詳細：あなたの次の1件、または「待っていてよい」という結論。案と履歴はその後。
- 登録：入力の順番。形式（輪読／ミーティング）を先に選ばせ、共通の仕組みと固有の入力の境界を見せる。
- 実行記録：エージェントの判断ではなく、プログラムが拒否した操作。

## 設計ルール

- 幹事の仕組みは汎用。画面の語彙は「会・参加者・案・同意・通知」で統一し、節・範囲・未消化といった輪読固有の語は詳細と登録の中だけで使う。
- 本の要素はプラグインの札（`.plugin`）の中だけに置く。ほかの画面は形式に依存しない。
- 色は「あなたの行動」と「進行表」にだけ使う。状態は記号と罫で示す。注意の暖色は失敗と成否不明のときだけ、1画面に1か所まで。
- 進行表は持ち時間を幅の比率で描き、変更前を薄い帯として下に並置する。差し替えず、必ず比較で見せる。
- 和文は Noto Sans JP、英数字は Inter。時刻・分数・金額は `.num`（等幅数字）で桁を揃える。
- 余白は 4 / 8 / 12 / 16 / 24 / 32 / 48 / 72px。角丸は面12px、操作8px、札は丸。影はダイアログだけ。
- 動きは1か所だけ。読み込み時に進行表の帯が伸びる。`prefers-reduced-motion` で止まる。
- 賛成数や必要人数はブラウザーで計算せず、受信した値をそのまま表示する。
- 参加者の定例入力は4項目のみ。自由文と辞退理由は設けない。
- 送信直後は必ず「受け付けました」を表示し、確定と区別する。競合を再現してもフォームの選択は保持する。

## まだ繋いでいないもの

APIには繋がっていません。`app.js` の `states` と `schedules` が表示用の固定データです。`.agent/decisions/api.md` の契約に合わせるのは、画面の形が決まった後に行います。
