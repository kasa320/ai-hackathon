# ISBNからの目次取得の取得元

記録日：2026-09-21。

## 決定事項

- ISBNからの目次取得は残し、取得元を国立国会図書館サーチ（NDLサーチ）の OAI-PMH に変える。出版情報登録センター（JPRO）のレコード `R100000137-I{ISBN13}` の `dcterms:tableOfContents` を使う。
- 目次が登録されていない本は、目次ページの写真か手入力に進む。画面では3つの入れ方（ISBN・写真・手入力）をいつでも切り替えられるようにした。
- 既存の LLM による Web 検索（`ORCAROUTER_SEARCH_MODEL` 設定時のみ）は、NDL に目次がない場合の追加手段として残した。

## 理由

ユーザーから「ISBNからの目次取得が実質的に意味をなしていない。原理的にできるか調べ、できなければ削除して画像か手入力にする」と依頼された。

事実（2026-09-21 に実際に照会して確認）：

- 以前の実装は、書名を openBD／NDL の OpenSearch で調べたあと、LLM の Web 検索で目次を探していた。検索用モデルが未設定の環境では、ISBN を入れても必ず画像の提出に進んでいた。
- openBD：技術書など8冊を照会し、目次（ONIX の TextType 04）は0冊。
- NDLサーチ OpenSearch・国立国会図書館の書誌（R100000002）：目次の項目がない。
- NDLサーチ OAI-PMH の JPRO レコード：9冊中5冊で目次を取得できた（42〜353項目）。新しい本ほど登録されている傾向。応答に10〜50秒かかることがあり、混雑時は429を返す。
- Google Books API はキーなしでは1日の上限に達していて（429）、照会できなかった。目次を返す項目がないという認識だが、ドキュメントでは確認していない（推測）。Open Library は照会した1冊が未収録（404）だった。

判断：JPRO の目次は出版社が登録した構造化データなので、LLM も取得元ページとの照合も要らない。対象は約半分の本に限られるため、写真・手入力への切り替えを常に用意する。

## 却下した選択肢

- 機能の削除：約半分の本で、正確な目次を自動で取り込めるため採らない。
- NDLサーチの書誌ページ（HTML）からの抽出：ページには目次が表示されるが、公式の API（OAI-PMH）で同じデータを取れるため、HTML の解析はしない。
- 出版社サイトの個別の解析：出版社ごとに形式が違い、保守できない。

## 制約・未確認

- JPRO の目次には階層の情報がない。部・第N章・Chapter N・1.1・1-1 などの番号の書き方から推定している。番号のない項目（まえがき・付録など）は章と同じ階層にし、COLUMN は章の下に置く。
- 項目が300件を超える場合は、細かい階層から省く。
- 利用条件：非営利なら申請不要。NDLサーチの API を使っている旨の表示が必要なため、画面に「国立国会図書館サーチ（出版情報登録センターの登録データ）から取得しました」と取得元のリンクを出している。JPRO データの二次利用条件は API の案内ページに記載がなく、未確認。
