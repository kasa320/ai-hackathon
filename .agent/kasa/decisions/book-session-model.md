# ブックとセッションのモデル

作成日: 2026-09-21

## 事実

- 既存の `sessions` は、作成時に案件・参加条件確認タスク・実行履歴を作る単位である。
- 輪読では、1冊を終えるまでに複数の開催回があり、次回の範囲・期間・所要時間は管理者が決める。

## 決定

- `reading_books` を親、`reading_book_slots` を予定回の枠とする。枠は `planned` / `active` / `completed`、実セッションIDは nullable とする。
- `sequential` は初回だけを作り、`all` は全枠を保存する。ただし両方とも初回だけを active にする。
- planned 枠は共通のセッション生成経路を通さないため、LLM・確認タスク・通知を起動しない。
- 進捗は計画確定ではなく、管理者が active 枠を明示完了した時点で、確定案の `covered_section_ids` を重複なしで反映する。

## 採用理由

既存の調整フローを実セッションだけに限定でき、未開始回が参加者に依頼や通知を出すことを構造上防げる。枠と実セッションを分離するため、将来の回数表示と、開始時の管理者入力を両立できる。

## 却下した選択肢

- **全セッションの調整を一斉開始**: 先の予定・担当条件は変わりやすく、不要な確認タスクと通知を発生させる。MVPの「次回だけを調整する」範囲にも合わない。
- **章を自動分割**: 章の重さや読書会の意図を機械的に推測すると不適切な範囲になり得る。今回は管理者が対象範囲を明示入力する。

## 提案

- 将来、枠ごとのメモや見積りを追加する場合も、planned 状態では共通調整フローを起動しない不変条件を維持する。
