# 開催日時をエージェントが決める（期間だけで登録する）

決定日：2026-09-21。関連：[サービス名とホーム画面](service-name-and-landing.md)、[自由文の解釈](free-text-interpretation.md)、[仕様書](../../decisions/spec.md)。

## 背景

`spec.md` 第4節と `plan.md` では「日程の自動調整は対象外」としていた。準備状況に応じた**再計画**を中心に据え、日程調整は既存サービスが多いので差別化にならない、という判断だった。

一方で、ホーム画面の見出しを「日程調整は、丸投げでいい。」に変えた。**登録画面では人間が日時を入力していた**ので、名乗っていることと中身が食い違っていた。

## 決めたこと（縮めた形）

「頻度を承認 → 日時を承認」の2段構えは作らない。**承認は1回**にして、既存の仕組みに載せる。

1. **回の登録は最小限**にする。入力は「開始日・終了目安日・1回の長さ」だけ。回の名前は省略でき、省くと「第N回」を自動で振る。
2. **日時は案（proposal）が決める**。頻度は同じ案の `frequency` に1行で書き、承認の対象は案そのもの1つだけにする。確定するのは**次の1回ぶん**で、期間の残りは文章で示すにとどめる。
3. **空き予定は「出られない日」だけ集める**。参加条件に `unavailable_dates` を足し、Web でも DM でも今までどおり1つの回答として受け取る。新しい画面は作らない。
4. **否決・不成立のときは既存の再計画ループ**をそのまま使う。案が棄却されれば版を上げて作り直し、上限を超えれば管理者判断待ち（`needs_owner`）に落ちる。ここは既に実装済みの動き。

## 「出られる日」ではなく「出られない日」を聞く理由

答えていない人を「出られる」とみなさないため。空き時間を申告させる形にすると、未回答を空きと誤読する余地が残る。出られない日だけを集めれば、未回答は「制約なし」ではなく「情報なし」のままで、案の検証では出席予定者の申告だけを使える。

## 多数決で押し切らないための作り

日時は過半数の同意で決まるが、**出られないと答えた人がいる日は案として成立しない**（`validateSchedule` が弾く）。同意の数で「出られない人」を上書きできないようにしている。候補がまったく作れないときは案を出さず、期間の見直しを管理者に返す。

## 実装の形

共通側（`coord`）は日時の決め方を知らない。用途側が任意インターフェース `coord.PlanScheduler` を実装したときだけ、確定時に案の日時を開催回へ反映する。`Snapshot` には `schedule_status`・`period_start`・`period_end` と判断時刻 `now` を足した。

| 保存 | 追加した列 |
| --- | --- |
| `sessions` | `period_start`・`period_end`・`schedule_status`（`proposed` / `confirmed`） |

`starts_at` は**常に値を持つ**。`proposed` の間は「回答期限を確保できる最初の日の19:00」を仮に入れておき、画面は `schedule_status` を見て「日時調整中」と出す。列を NULL 許容にしなかったのは、回答期限（`dueAt`）・再試行の打ち切り（`retryCutoff`）・一覧の並び順がすべて `starts_at` を前提にしており、そこを崩すと影響範囲が読めなくなるため。

既存のDBを作り直さずに済むよう、起動時に不足している列だけ `ALTER TABLE` で足す（`store.addMissingColumns`）。

## 残したもの・やらなかったこと

- **日時を直接指定する登録は残した**。`starts_at` を送れば今までどおり `schedule_status="confirmed"` で登録される。既存のデモ用データ（`devapi`）と評価ケースはこの経路のまま動く。
- **期間全体の回をまとめて作らない**。確定するのは次の1回だけ。複数回分の自動計画は引き続き対象外。
- **頻度だけを先に承認する段は作らない**。合意を2周回すとデモの尺と実装量が倍になり、凍結（9/22 12:00）までに両方仕上がらない見込みだった。

## 評価への影響（未処理）

`spec.md` 第8節は「予定変更の調整負担」を主比較にしている。日程調整を主役にするなら、LINE 側の集計対象に日程調整のメッセージを含めるかを決め直す必要がある。**この判断はまだしていない。**
