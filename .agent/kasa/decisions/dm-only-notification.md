# 通知の送信条件：チャンネルIDがなくても、本人宛てのDMは送る

決定日：2026-09-21。関連：[Discord上の対話型エージェント](discord-interactive-agent.md)。

## 背景（観測した事実）

個人チャット（DM）に通知が届かなかった。原因は設定条件で、`DISCORD_CHANNEL_ID` が空だと `Config.DiscordNotifyConfigured()` が false になり、送信先が `LogSender`（サーバーログに出すだけ）に差し替わっていた。Botトークンは設定済みで、DM を開く権限もあったが、**チャンネルIDが無いというだけで DM も含めて何も送られていなかった**。

DM を優先する仕組み自体（`task_requested`・`reminder` はまず DM、確実に失敗したときだけチャンネルへ退避）は入っていたので、そこまで届いていなかったことになる。

## 決めたこと

1. `DiscordNotifyConfigured()` の条件を **Botトークンだけ**にする。チャンネルIDは必須ではなく、次の2つの役割に限る。
   - DM が確実に失敗したときの退避先
   - 名指しの相手がいない全員宛て連絡（`plan_confirmed`）の送り先
2. チャンネルIDが未設定のときは、**種類にかかわらず、名指しした本人へDMを送る**（`needs_owner` も本人に届く）。退避先が無いので、DM の失敗はそのまま失敗として記録する。
3. 宛先も退避先も無い通知（チャンネル未設定での `plan_confirmed`）は、送信を試みずに **failed として記録**する。届いていないのに送信済みにしない。
4. DM を使うかどうかの判断は `DiscordSender` に集約する。`Dispatcher` は「名指しした本人」を渡すだけにして、判断が2か所に分かれないようにする。

## 理由

成否の記録を曖昧にしないことを優先した。黙ってログに落とす（元の挙動）と、画面上は「送信待ち」のまま時間が過ぎ、届かない理由が誰にも分からない。届かないなら failed として残し、理由が設定にあることを README と `.env.example` に書く。

## 影響

- `.env` の `DISCORD_CHANNEL_ID` は空のままでよい。全員宛ての確定連絡もチャンネルに流したいなら設定する。
- Bot と利用者に共通のサーバーが無い場合、DM は Discord 側で拒否される（403）。これはコードでは直せないので、失敗として記録するにとどめる。
