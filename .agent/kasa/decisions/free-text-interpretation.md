# 自由文の解釈：LLMは「決められた項目の値を決める」だけ

決定日：2026-09-20。関連：[認証とDiscord連携の方式](auth-and-discord-linking.md)。

## 背景

参加条件は構造化フォームに固定し、自由文は受け付けていなかった（辞退の `reason` は400で拒否）。私的な原文を保存しないための安全側の判断だったが、次の2つの副作用があった。

- 入力の敷居が高い。実運用のLINEでの調整と比べ、Webのフォームを開く負担が残る。評価（spec.md 第8節）で測る「参加者全体の調整操作数」が減りにくい。
- 仕様第4節の表で「AIが判断すること」に挙げた「回答の意味を読み取る」が未実装のままで、LLMを使う意味が「代案を考える」に偏っていた。

Discord上での対話で予定を決める案も検討したが、別記録のとおり今回は見送る。

## 決めたこと

自由文を受け付ける。ただし **LLMにできるのは、プログラムが定義した項目の値を決めることだけ**とする。

1. プログラムが必要な項目（変数）を定義する。用途側が JSON Schema で公開する（`PreparationInterpreter.PreparationSchema`）。
2. LLMには、その型のツールを1つだけ渡す。ツールの引数以外に出力経路がない。
3. 取り出した値はサーバーが用途の規則で再検証する（`ValidatePreparation`）。通らなければ検証エラーを返してやり直させ、最大2回で諦める。
4. 結果は**保存しない**。本人が画面で確認・修正し、通常の参加条件の送信で初めて保存される。
5. 原文はアプリDB・実行ログに保存せず、解釈用モデルへの送信にだけ使う。共有用モデル・共有画面・通知には渡さない。

### 残存リスクへの手当て

型で閉じても防げないものが2つあり、それぞれ別の手段で潰す。

| 残存リスク | 手当て |
| --- | --- |
| 値の汚染（他人について書かれた内容を、その人の値として取り込む） | 発話者と対象者を束縛する。対象者は常に呼び出した本人で、メンバーIDを入力から受け取らない。抽出時にAIへ渡すのも節一覧と持ち時間だけで、他のメンバーの回答は渡さない |
| 誤抽出（「15分くらいなら…」を確定値として扱う） | 本人確認ステップを必須にする。読み取れない項目は推測せず `unclear` に入れ、担当しない側に倒す。保存は本人の明示操作でのみ行う |

「無関係な指示を妨害する」のではなく、**受け皿を作らない**。同意・引き受け・確定・通知を作るツールを与えていないので、発言に含まれる指示は型の上で行き場がない。

## 却下した選択肢

### 自由文をそのまま保存し、あとからAIに読ませる

原文がアプリDB・実行ログ・共有用モデルの入力に入り、仕様第4節の約束を守れない。解釈用モデルへの送信に限定し、構造化結果だけを残す方式にした。

### LLMの出力をそのまま参加条件として保存する

本人の確認を挟まないと、誤抽出がそのまま引き受け・同意の前提になる。仕様第4節の「自由文からの解釈は本人が確認・修正できる」に反する。

### 自由文の解釈をDiscordのチャットで行う

原文がDiscord側のサーバーに残り続け、こちらで制御できないため「原文を保存しない」を半分しか守れない。まずWebの入力欄で実装する。抽出層は入口に依存しないので、Discordに載せ替えるときに再利用できる。

### プロンプトで「無関係な指示を無視せよ」と命じるだけにする

指示と指示のいたちごっこになり、検証できない。出力経路を型で閉じる方式なら、指示に従ったかどうかによらず結果が制約される。

### 解釈のLLM呼び出し回数を案件の上限（`cases.llm_call_count`）に加算する

参加者が繰り返し解釈を呼ぶと、計画側の予算を使い切らせられる。呼び出しは `llm_calls` に記録して費用表示には含めるが、案件のカウンターには加算しない。解釈は1回あたり最大2回、案件の総呼び出し数が上限に達している場合は解釈を断る。

## 実装の範囲

- `POST /api/sessions/{session_id}/preparations/me/interpretations`（保存しないため `Idempotency-Key` は不要、CSRFと所属の検証は通常どおり）
- `coord.Interpreter` / `coord.PreparationInterpreter`（共通側は項目の意味を解釈しない）
- `agent.LLMInterpreter`（`AGENT_MODE=llm`）と `coord.DraftOnlyInterpreter` + `reading.DraftInterpret`（`AGENT_MODE=fake`、規則だけの仮の抽出）

## 残る確認事項

- 実モデルでの抽出精度。特に「自信がない」「たぶん」の扱いが担当しない側に倒れるか。規則版との比較を評価に含める。
- 画面側の確認UI（読み取れなかった項目の見せ方）。フロント担当と分担を確認する。
