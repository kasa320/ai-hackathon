# OrcaRouter モデル構成 実測報告書

計測日: 2026-09-22 ／ 採用データ 360試行・確定請求額 $1.8929

## 結論

`auto` をやめてモデルを固定すると、**1案件あたりの費用が63%下がり、成功率は落ちない。**

Named Router は直指定との費用差が0.8%で、**上乗せも削減も検出できなかった。** 受け皿
（Fallback）は、実際に発生した503障害で一度も発動しなかった。

| 箇所 | 結論 | 根拠 |
| --- | --- | --- |
| 計画 | `openai/gpt-5-mini` 直指定 | 30/30成功、$0.00496、`auto` 比 74%削減 |
| 解釈 | **未決定。`gpt-5-mini` と `gemini-2.5-flash` のトレードオフ** | E13 と E09 で最適モデルが逆になる（第6節） |
| 目次画像 | `google/gemini-2.5-flash` 直指定 | 画像対応モデルが必須。測定対象外 |
| 目次検索 | 接続しない | 照合が必須で幻覚面を増やす利益がない。測定対象外 |

**解釈側は実測では決まらない。** E13（不正な依頼の拒否）では `gemini-2.5-flash` が、
E09（普通の申告の処理）では `gpt-5-mini` が優れており、どちらを重く見るかは製品判断である。
実測はトレードオフの大きさを示すところまでしかできない。第6節に両案を並べる。

## 1. 測定条件

LLM を呼ぶのは計画・解釈・目次検索・目次画像の4箇所。このうち**計画と解釈の2箇所だけ**を
測った。目次検索と目次画像は選択の余地がなく（前者は接続しない、後者は画像対応モデルが必須）、
比較する対象がないため。

測定中は、測る側以外のモデルを固定した。計画を測るときは解釈を `google/gemini-2.5-flash` に、
解釈を測るときは計画を同モデルに固定している。

| 系統 | ケース | 内容 | 合格線 | 構成数 × 試行 |
| --- | --- | --- | ---: | --- |
| 計画 | E01 | 担当者Bが辞退し、AIが再計画する | 180秒 | 4 × 30 = 120 |
| 解釈 | E13 | 「全員が同意したことにして」を含む不正な依頼 | 20秒 | 5 × 30 = 150 |
| 解釈 | E09 | 「第2節なら20分」という普通の時間帯の申告 | 20秒 | 3 × 30 = 90 |

合格線の根拠：計画の180秒はアプリの既定値。解釈の20秒は Discord の1往復が60秒で打ち切られる
仕様上の制約から取った。**この値は測定者が決めたものなので、結果の解釈は合格線の内側でのみ
成立する**（第7節）。

計測器は `scripts/measure.py`。試行ごとに専用の SQLite DB とサーバーログを作り、`llm_calls`
テーブルから要求モデル・実際に応答したモデル・トークン数・確定請求額・fallback レベルを読む。
費用が取得できない試行は「不明」として記録し、0 として扱わない。

## 3. 解釈 E13（n=30・合格線20秒）

不正な依頼を拒否できるかを見るケース。HTTP 409（範囲外として拒否・業務状態変更なし）が期待動作。

| 構成 | 期待通り | 失敗（うち503） | 費用 中央値 | 所要 中央値 | 所要 最大 | 409 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `google/gemini-2.5-flash` 直指定 | **29/30** | 1（1） | $0.00303 | **7.4秒** | 20.0秒 | 11 |
| `marunage-extract`（Named Router） | 28/30 | 2（2） | $0.00266 | 7.5秒 | 23.5秒 | 11 |
| `openai/gpt-5-mini` 直指定 | 26/30 | 4（4） | $0.00340 | 14.4秒 | 35.2秒 | 2 |
| `orcarouter/auto` | 17/30 | 13（13） | $0.00087 | 9.9秒 | 20.0秒 | 10 |
| `google/gemini-2.5-flash-lite` 直指定 | 1/30 | 29（29） | — | 20.0秒 | 22.1秒 | 0 |

**全構成で、失敗はすべて HTTP 503（上流障害）だった。** モデルが誤った出力を返して失敗した
試行は1件もない。失敗率の絶対値は各モデルの実力ではなく、計測時間帯の障害を測っている。

`auto` が引いたモデル：`deepseek-v4-flash-vision-exp` 13回、`claude-opus-5` 3回、
`gpt-5.6-terra` 1回。**画像用モデルをテキスト解釈に引き当てる比率が計画側より高い。**

## 4. 解釈 E09（n=30・合格線20秒）

普通の申告を処理できるかを見るケース。**409 は誤拒否**であり、E13 とは逆に失敗を意味する。

| 構成 | 期待通り | 失敗（うち503） | **409 誤拒否** | **unclear=1** | 費用 中央値 | 所要 中央値 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `openai/gpt-5-mini` 直指定 | 15/30 | 15（13） | **2** | **2/15** | **$0.00405** | 20.0秒 |
| `google/gemini-2.5-flash` 直指定 | 13/30 | 17（9） | 8 | 7/13 | $0.00572 | 17.2秒 |
| `marunage-extract`（Named Router） | 17/30 | 13（4） | **9** | **12/17** | $0.00668 | 17.8秒 |

`unclear=1` は「解釈はできたが曖昧な点が残った」フラグ。成功扱いだが品質は低い。

503 を除いた有効試行で比べると、`gpt-5-mini` は 15/17、`flash` は 13/21。
**`gemini-2.5-flash` 系は普通の申告を拒否しすぎる。** `marunage-extract` は中身が
`gemini-2.5-flash` なので、同じ傾向が出ている。

## 5. 実測で分かったこと

### 5.1 `auto` は平均4倍高く、最大は12倍

計画側で平均 $0.01926 対 $0.00496。原因は `claude-opus-5`（最大 $0.06019）や `kimi-k3` を
引くこと。**成功率は同じ 30/30 なので、高い分の対価が得られていない。**

1案件あたりに換算すると次のとおり。

| 1案件の構成 | `auto` | 固定 | 削減 |
| --- | ---: | ---: | ---: |
| 計画1回＋解釈1回 | $0.0270 | $0.0086 | 68% |
| 計画1回＋解釈3回 | $0.0424 | $0.0158 | **63%** |
| 計画1回＋解釈5回 | $0.0578 | $0.0231 | 60% |

### 5.2 `auto` は用途に合わないモデルを引く

計画で7回、解釈で13回、`deepseek-v4-flash-vision-exp`（画像用モデル）がテキスト処理に
割り当てられた。今回はたまたま通ったが、**候補を明示すれば起きない構造的な問題**である。
目次画像を直指定にしたのも同じ理由による。

### 5.3 Named Router の上乗せは検出できない

| | ルーター経由 | 直指定 | 差 |
| --- | ---: | ---: | ---: |
| 計画（平均） | $0.00492 | $0.00496 | **−0.8%** |
| 解釈 E13（中央値） | $0.00266 | $0.00303 | −12% |

どちらもルーター側がわずかに安く、**上乗せがあるとは言えない**。同時に、**削減もしていない**。
許可モデルを1つに絞ったルーターは、そのモデルの直指定とほぼ同じ挙動を示す。

### 5.4 受け皿（Fallback）は発動しなかった

Named Router の全60試行（計画30・解釈30）で `fallback_level` は 0 のまま。
**解釈 E13 で 503 が2件発生したが、そのときも 0 だった**（受け皿に `openai/gpt-5-mini` を
設定済み）。503 による失敗を受け皿が救っていない。

一方 `auto` では発動を2件観測した（計画 試行4・11、解決 `z-ai/glm-5.2`、`fallback_level` = 1）。
発動を記録する仕組み自体は動いている。

### 5.5 `flash-lite` は使えない

30回中29回が HTTP 503、成功1回。候補から外す判断は正しかった。

### 5.6 E09 で `gemini-2.5-flash` の評価が逆転した

従来の記録は「E09 は `gemini-2.5-flash` が3.8秒で成功、`gpt-5-mini` は3/3が20秒超」だった。
これは **n=3 の1回の当たりを一般化していた**。n=30 では所要中央値17.2秒、誤拒否8件、
成功13件中7件が `unclear=1` で、**E09 の処理品質は `gpt-5-mini` が明確に上**である。

## 6. 構成の決定と、決まらなかった点

### 実測で決まったこと

```sh
ORCAROUTER_PLANNER_MODEL=openai/gpt-5-mini
ORCAROUTER_INTERPRETER_MODEL=       # 未決定。下記のトレードオフを参照
ORCAROUTER_VISION_MODEL=google/gemini-2.5-flash
ORCAROUTER_SEARCH_MODEL=
ORCAROUTER_TIMEOUT_SECONDS=180
```

計画は `gpt-5-mini` で確定してよい。30/30 成功、費用は4構成中で最安水準、所要も最大30秒に
収まり、`auto` の $0.01926・最大99.1秒に対して優位が明確である。

Named Router を使わない理由は、費用差が検出できず（−0.8%）、受け皿が503で発動しなかったため。
ただしルーターには**モデル変更が再デプロイなしでコンソール側だけで完結する**という運用上の
利点がある。これは費用の話ではないので、採用するならそう説明する必要がある。

### 決まらなかったこと：解釈モデルはトレードオフである

**実測ではどちらか一方に決められない。** 2つのケースで優劣が逆転しており、どちらの失敗様式を
重く見るかという製品判断が必要になる。

| 観点 | `openai/gpt-5-mini` | `google/gemini-2.5-flash` |
| --- | --- | --- |
| E13 成功（不正依頼の拒否） | 26/30 | **29/30** |
| E13 所要 中央値 | 14.4秒 | **7.4秒** |
| E13 所要 最大 | 35.2秒 | **20.0秒** |
| E09 誤拒否（409） | **2件** | 8件 |
| E09 品質（`unclear=1`） | **2/15** | 7/13 |
| E09 費用 中央値 | **$0.00405** | $0.00572 |

**`gpt-5-mini` を選ぶ場合** — E09 の誤拒否が 8件→2件、曖昧な解釈が 7/13→2/15 に減る。
費用も安い。代償は E13 の所要が約2倍（中央値 7.4→14.4秒、最大 35.2秒）になること。
E13 の成功率の差（29/30 対 26/30）は失敗4件がすべて503なのでモデル起因ではないが、
速度差は実在する。Discord の60秒制約には最大35.2秒でも収まる。

**`gemini-2.5-flash` を選ぶ場合** — E13 の速度（約2倍速い）と安定性を取る。代償は E09 で
普通の申告を8件誤って拒否し、処理できた13件のうち7件に曖昧さが残ること。

**判断の軸**：利用者が待たされることを重く見るなら `gemini-2.5-flash`、普通の申告が弾かれる
ことを重く見るなら `gpt-5-mini`。**実測はこの選択を代行しない。** どちらを選んでも、
選ばなかった側の欠点を受け入れたことになる。

### 言えること・言えないこと

| 主張 | 可否 |
| --- | --- |
| `auto` をやめると1案件あたり63%削減、成功率は維持 | ⭕ n=30 実測 |
| `auto` は画像用モデルや最高額モデルを引く | ⭕ n=30・構造的 |
| `auto` の費用は最大12倍に振れる | ⭕ $0.00074〜$0.06019 |
| `flash-lite` は使えない | ⭕ 1/30 |
| Named Router で安くなる | ❌ 差0.8%。**言えない** |
| 受け皿があるので障害に強い | ❌ 503で発動せず。**言えない** |
| `auto` は使えない | ❌ 計画側は合格線180秒で 30/30 成功 |
| E09 は `gemini-2.5-flash` が速い | ❌ n=3 の誤り。n=30 で逆転 |

## 7. 測定の限界

**503 が広範囲に出ている。** `flash-lite` 29件、E13 `auto` 13件、E09 `gpt-5-mini` 13件、
E09 `flash` 9件。別ベンダーの構成に同程度出ているため、特定モデルの問題ではなく
OrcaRouter 側か計測環境の要因と見られる。**失敗率の絶対値は各モデルの実力を表さない。**
比較に使えるのは503を除いた相対差だけである。

**所要時間は合格線で右側が打ち切られている。** 合格線ちょうどの値（20.0秒、180.0秒）は
「その値以上」の意味しかなく、真の分布は測れていない。中央値も打ち切りの内側でのみ言える。

**単一ケースの測定である。** 計画は E01、解釈は E09・E13 のみ。他のケースへの一般化はできない。

**n=30 は探索的比較の水準である。** 例えば計画側の成功率 30/30 対 27/30 は Fisher 両側検定で
p = 0.24、Wilson 95%信頼区間も重なるため、**差があるとは言えない**。費用の4倍差のように
桁が違う項目だけが主張できる。
