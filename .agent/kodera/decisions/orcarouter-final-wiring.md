# LLM を呼ぶ4か所への OrcaRouter の最終接続構成

更新日: 2026-09-22
対象ブランチ: `feat/member-leave`

## 背景と解決したい問題

LLM を呼ぶ箇所は4つある（計画・解釈・目次検索・目次画像）。それぞれに OrcaRouter を
どう接続するかを、推測ではなく実測で決める。根拠となる全データは
[orcarouter-model-cost-measurements.md](orcarouter-model-cost-measurements.md) にある。

計測は79試行、確定請求額の合計 $0.5275。合格線は測定の都合ではなく製品要件に合わせた。

## 決定事項

| 箇所 | 接続の形 | 指定する値 | 状態 |
| --- | --- | --- | --- |
| 解釈 | Named Router | `orcarouter/marunage-extract` | **決定** |
| 目次検索 | **接続しない** | `ORCAROUTER_SEARCH_MODEL` は空 | **決定** |
| 目次画像 | **モデル直指定** | `google/gemini-2.5-flash` | **決定** |
| 計画 | Named Router | `orcarouter/marunage-plan` | **決定** |

### 計画の合格線を訂正した経緯

当初、計画の合格線を60秒としたが、**この値に根拠がなかった**。解釈側の60秒（Discord の
1往復の打ち切りという仕様上の制約）を流用しただけで、計画に当てはめる理由がない。

アプリのコードから逆算すると、計画の実際の締切は「回答期間（`MinResponseWindow` = 30分）を
確保できるうちに案ができていること」で、分〜十数分の単位。人間の回答待ちが支配的なので、
モデルの応答が数分かかっても実害がない。呼び出し1回の上限（`ORCAROUTER_TIMEOUT_SECONDS`）の
既定値も180秒である。

**合格線180秒で取り直したところ、結論が変わった。**

| 構成 | 60秒 | 180秒 |
| --- | --- | --- |
| `orcarouter/auto` | 0/3 | **3/3（59 / 58 / 11秒）** |
| `orcarouter/marunage-plan` | 0/4 | 2/3（118 / 9 / 59秒） |

`auto` の 0/3 は**私が引いた線が作った結果**だった。59秒・58秒という値は60秒の直前であり、
再試行が1回入れば即座に超える。線がちょうど結果を分ける位置にあった。

### `marunage-plan`（計画）— 決定

```
Strategy:  バランス（候補が1つなので戦略は結果に影響しない）
Allowed:   openai/gpt-5-mini
弱/強プール: 設定しない
Fallback:  google/gemini-2.5-flash
```

合格線180秒での実測（各3試行）。

| 構成 | 成功 | 所要（API） | 確定額 | 平均 | 費用のばらつき |
| --- | ---: | --- | --- | --- | --- |
| `openai/gpt-5-mini` | 3/3 | 16 / 16 / 20秒 | $0.0046 / $0.0046 / $0.0056 | $0.00494 | **1.2倍** |
| `google/gemini-2.5-flash` | 3/3 | 31 / 22 / 16秒 | $0.0042 / $0.0046 / $0.0063 | $0.00502 | 1.5倍 |
| `orcarouter/auto` | 3/3 | 59 / 58 / 11秒 | $0.00082 / $0.00076 / $0.01248 | $0.00469 | **16倍** |
| `orcarouter/marunage-plan`（ゲート） | 2/3 | 118 / 9 / 59秒 | $0.1103 / $0.0046 / $0.0473 | $0.05409 | **24倍** |

**根拠は「安さ」ではなく「予測できること」。**

平均費用は `auto` $0.00469、`gpt-5-mini` $0.00494、`gemini-2.5-flash` $0.00502 で**ほぼ同じ**。
`auto` が安いという主張は成り立たない。差が出るのは**分散**である。

- `auto` は試行ごとに `z-ai/glm-5.3-flash`（安い）と `openai/gpt-5.6-terra`（16倍高い）を
  引き分けた。平均が同じでも、**1回あたりがいくらで何秒かかるか予測できない。**
- `gpt-5-mini` は 16〜20秒・$0.0046〜0.0056 に収まる。**最も速く、最もばらつきが小さい。**

製品としては「1回いくらか分かる」「何秒で返るか分かる」ことに意味がある。
利用者に待ち時間を説明でき、費用の見積もりが立つ。

**アダプティブゲートを外す理由。** `marunage-plan` は 2/3 で成功するようになったが、
費用が $0.0046〜$0.1103 の**24倍**に振れ、平均は他の11倍。`claude-sonnet-5` に振られた
2試行のうち1つは `model_error` で失敗した。難易度で振り分ける利益が観測できない。

**Fallback を `gemini-2.5-flash` にする理由。** 別ベンダー（Google）で、3/3 成功を確認済み。
`claude-haiku-4.5` は計測期間を通じて 503 で、一度も動作を確認できていない。

### `marunage-extract`（解釈）— 決定

```
Strategy:  バランス（候補が1つなので戦略は結果に影響しない）
Allowed:   google/gemini-2.5-flash
弱/強プール: 設定しない
Fallback:  openai/gpt-5-mini
```

根拠は3つ。

**1. `gemini-2.5-flash` が両ケースで最速だった。**

| ケース | `gemini-2.5-flash` | `gpt-5-mini` | `gemini-2.5-flash-lite` |
| --- | --- | --- | --- |
| E09 | **3.8秒で成功** | 3/3 が20秒超 | 1.8秒 or 打ち切り |
| E13 | 4.6 / 7.5 / 16.8秒 | 14.5 / 16.3 / 20.3秒 | 3/3 が 503 |

30試行中、**タイムアウトがゼロだったのは `flash` だけ**。遅かった2回（35.3・35.4秒）も
20秒の打ち切り＋再試行の合計で、1回の呼び出し自体は4〜10秒に収まっている。

**2. 最安戦略は使えない。** 単価は `gpt-5-mini`（$0.25/$2.00）が `gemini-2.5-flash`
（$0.30/$2.50）より安いため、最安戦略は**実測で遅い方を選んでしまう**。
単価の安さと実際の速度が逆転している。候補を1つに絞れば戦略に左右されない。

**3. 安全性では差がない。** E13 で `flash` も `gpt-5-mini` も、同意記録を作らず、
不適切な依頼は `out_of_scope` として拒否した。強いモデルに上げる安全上の理由がない。

**`gemini-2.5-flash-lite` を外す理由**：1.8秒で返る回と打ち切りに達する回に二極化し、
中間の値がない。E13 の最終計測では 3/3 が 503 だった。Discord の1往復は60秒で
打ち切られるため、当たり外れのある構成は採用できない。

**Fallback を `gpt-5-mini` にする理由**：別ベンダー（OpenAI）で、E13 を 2/3 期待通り＋
1 安全拒否で処理できている。遅いが動くことは確認済み。`claude-haiku-4.5` は計測期間を
通じて 503 で、一度も動作を確認できていない。**動くと確認したものを受け皿にする。**

### 目次検索を接続しない理由 — 決定

サーバーが取得元ページとの照合を必須にしているため、検索が外れても写真提出に落ちるだけで、
得られるものが小さい。提出前日に幻覚の発生面を増やす利益がない。
`spec.md` も「目次の取得が間に合わなければ、節の手入力で登録できる状態を維持する」としている。

### 目次画像を直指定にする理由 — 決定

実測で `orcarouter/auto` が `deepseek/deepseek-v4-flash-vision-exp`（画像用）を
テキスト処理に引き当てた。モダリティの取り違えは実際に起きる。
画像の書き写しは振り分ける余地のない決定的な作業なので、ルーターにする意味がない。

## `orcarouter/auto` より優れていると言えるか

**結論を先に書くと、「安いから」ではなく「予測できるから」である。** 平均費用では `auto` に勝てない。

### 平均費用では差がない（計画側・合格線180秒・各3試行）

| 構成 | 平均費用 | 最小 | 最大 | ばらつき |
| --- | --- | --- | --- | ---: |
| `orcarouter/auto` | **$0.00469** | $0.00076 | $0.01248 | **16倍** |
| `openai/gpt-5-mini` | $0.00494 | $0.0046 | $0.0056 | 1.2倍 |
| `google/gemini-2.5-flash` | $0.00502 | $0.0042 | $0.0063 | 1.5倍 |

平均は `auto` がわずかに安い。**「候補を絞れば安くなる」という主張は成り立たない。**

差が出るのは分散である。`auto` は試行ごとに `z-ai/glm-5.3-flash` と
`openai/gpt-5.6-terra`（16倍高い）を引き分けた。所要時間も 11〜59秒に振れる。
`gpt-5-mini` は 16〜20秒・$0.0046〜0.0056 に収まる。

### 実測で言えること

**1. 費用と所要時間の予測可能性**

`auto` は1回あたりの費用が16倍、所要時間が5倍に振れる。候補を1つに絞れば、
費用は1.2倍、所要時間は1.25倍の幅に収まる。
**利用者に待ち時間を説明でき、費用の見積もりが立つ。**

**2. モデル選択の制御可能性**

`auto` が実際に選んだモデル:

| 呼び出し | 選ばれたモデル | 結果 |
| --- | --- | --- |
| 計画 E01 | `z-ai/glm-5.3-flash` | 成功・$0.00076〜0.00082・58〜59秒 |
| 計画 E01 | `openai/gpt-5.6-terra` | 成功・$0.01248・11秒 |
| 解釈 E13 | `anthropic/claude-opus-5`（カタログ最高額 $5/$25） | 安全拒否・$0.046776 |
| 解釈 E13 | `deepseek/deepseek-v4-flash-vision-exp`（画像用） | HTTP 409 |
| 解釈 E13 | `z-ai/glm-5.2` | HTTP 409 |

**用途に合わないモデル（画像用）を引く。** これは試行数に依存しない構造的な差で、
候補を明示すれば起きない。

**3. 解釈側では費用差が実際に大きかった**

解釈 E13 で `auto` が `claude-opus-5` を引いた1件は **$0.046776**。
候補を絞った構成は $0.0017〜0.0076 で、**6〜28倍**の差があった。
ただし `auto` の費用が取れたのは1試行だけで、これが典型かは分からない。

### 実測では言えないこと

**1. 「`auto` は使えない」とは言えない。**
計画側では合格線180秒で 3/3 成功した。当初 0/3 だったのは、**私が根拠なく引いた
60秒の合格線が作った結果**である。59秒・58秒は60秒の直前で、線が結果を分ける位置にあった。

**2. 解釈側の `auto` の所要時間は測っていない。**
打ち切りに達した試行は「合格線以上」の意味しかない。合格線を上げれば通る可能性がある。

**3. 試行数が足りない。** 各3試行。統計的な差は主張できない。

**4. 目次画像について `auto` と比較していない。**
直指定の根拠は「解釈でモダリティの取り違えが起きた」という別の箇所での観測からの推論である。

### したがって主張できる範囲

| 主張 | 可否 |
| --- | --- |
| `auto` より**予測できる**（費用16倍→1.2倍、所要5倍→1.25倍） | ⭕ 実測 |
| `auto` は用途に合わないモデルを引く（画像用・最高額） | ⭕ 実測・構造的 |
| `auto` より**平均費用が安い** | ❌ **ほぼ同じ。むしろ auto がわずかに安い** |
| `auto` は使えない | ❌ 計画側では 3/3 成功する |
| `auto` より速い | ⭕ 計画側のみ（16〜20秒 対 11〜59秒） |

**「`auto` より優れている」ではなく、「`auto` は何を使うか制御できず、費用と所要時間が
予測できない。候補を絞れば、平均費用を変えずに予測可能にできる」**という言い方にとどめる。

## なぜ2か所だけルーターなのか

ルーターの価値は**費用ではなく信頼性**にある。OrcaRouter はトークンの上乗せ 0% で、
Fallback は発動しない限り課金されないため、**費用は直指定と完全に同じ**。

一方、計測期間中に 503 を繰り返し観測した（`claude-haiku-4.5` が数時間、E13 で5試行）。
**プロバイダは実際に落ちる。** 直指定だとそこで止まるが、Fallback があれば別ベンダーへ逃げられる。

資料が挙げる Named Router の3つの要点のうち、このアプリで採用するのは2つ。

| 要点 | 採用 | 根拠 |
| --- | --- | --- |
| 候補モデルを絞る | ⭕ | `auto` が `claude-opus-5`（1件 $0.0468）や画像用モデルを引いた |
| 受け皿（Fallback）を1本置く | ⭕ | 503 を繰り返し観測した |
| 必要な時だけ強いモデルへ上げる | ❌ | 計画では逆効果、解釈では候補を絞れば不要 |

## 実装対象ファイル

コードの変更はない。`.env` の値だけを変える。

```sh
ORCAROUTER_PLANNER_MODEL=orcarouter/marunage-plan
ORCAROUTER_INTERPRETER_MODEL=orcarouter/marunage-extract
ORCAROUTER_VISION_MODEL=google/gemini-2.5-flash
ORCAROUTER_SEARCH_MODEL=
ORCAROUTER_TIMEOUT_SECONDS=60
```

Named Router 2本の設定変更は OrcaRouter のコンソールで行う（管理APIは存在しない）。

## 却下した案

### 案1: すべて直指定にしてルーターを使わない

費用は同じで設定は単純になる。しかし Fallback を失う。計測期間中に実際に 503 が頻発した以上、
プロバイダ障害で止まる構成を選ぶ理由がない。

### 案2: アダプティブゲートを維持する

資料が★付きで推す設計であり、「難易度で振り分けています」と説明できる魅力がある。
しかし計画側では 4/4 失敗という実測がある。**動かない機能を設定に残して説明に使うのは、
実測して設計に反映したことにならない。**

### 案3: 解釈の弱プールに `gemini-2.5-flash-lite` を残す

成功時 1.8秒で全構成中最速。しかし二極化して中間がなく、最終計測では 3/3 が 503。
Discord の1往復は60秒で打ち切られるため、半分の確率で間に合わない構成は採用できない。

### 案4: Fallback を `claude-sonnet-5` にする

計画で 3/3 `model_error` だった。受け皿が制約を満たせないのでは意味がない。

### 案5: 解釈の Fallback を `claude-haiku-4.5` にする

別ベンダー（Anthropic）で単価も安く、当初はこれを推した。しかし計測期間を通じて
上流が 503 を返し続け、**一度も動作を確認できていない**。動作未確認のモデルを
受け皿に置くのは、受け皿が無いのと変わらない。実測で動いた `gpt-5-mini` を選ぶ。

### 案6: 解釈の候補を2つ（`gemini-2.5-flash` と `gpt-5-mini`）にする

候補が多いほど障害に強いという考え方はある。しかし最安戦略は単価で選ぶため、
**実測で遅い `gpt-5-mini` が常に選ばれてしまう**。速度で選ぶ戦略は用意されていない。
候補を1つに絞り、もう1つは Fallback に置くことで、通常は速い方を使い、
落ちたときだけ遅い方へ逃げる形にできる。

## 後で必ず検討・実装すること

- **`anthropic/claude-haiku-4.5` は未検証。** 計測期間を通じて上流が 503 を返し続けたため、
  速度も品質も測れていない。Fallback として選んだが、復旧後に確認が要る。
- `extra_body.models` による明示的なフェイルオーバー。Named Router の Fallback とどちらが
  適切かは未比較。`fallback_level` を記録する器はあるが、発動を観測できていない。
- 所要秒は合格線で右側打ち切りされている。真の分布を知るには上限を上げた再計測が要る。
- 試行数は各3回。`evaluation.md` が求める E02・E03 は未実施。
