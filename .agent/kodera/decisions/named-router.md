# Named Router をどう使うか

更新日: 2026-09-22 ／ 実測79試行・確定請求額 $0.5275 にもとづく

## 結論

| 箇所 | 接続 | 設定 |
| --- | --- | --- |
| **計画** | Named Router `marunage-plan` | Allowed: `openai/gpt-5-mini`<br>Fallback: `google/gemini-2.5-flash` |
| **解釈** | Named Router `marunage-extract` | Allowed: `google/gemini-2.5-flash`<br>Fallback: `openai/gpt-5-mini` |
| **目次検索** | 接続しない | `ORCAROUTER_SEARCH_MODEL` は空 |
| **目次画像** | モデル直指定 | `google/gemini-2.5-flash` |

どちらのルーターも **候補1つ＋別ベンダーの受け皿**。戦略は候補が1つなので結果に影響しない。
弱プール・強プール（難易度による振り分け）は**使わない**。

```sh
ORCAROUTER_PLANNER_MODEL=orcarouter/marunage-plan
ORCAROUTER_INTERPRETER_MODEL=orcarouter/marunage-extract
ORCAROUTER_VISION_MODEL=google/gemini-2.5-flash
ORCAROUTER_SEARCH_MODEL=
ORCAROUTER_TIMEOUT_SECONDS=180
```

---

## 根拠1：ルーターの価値は「安さ」ではなく「予測できること」

計画側（E01・合格線180秒・各3試行）の実測。

| 構成 | 成功 | 所要 | 平均費用 | 最小〜最大 | ばらつき |
| --- | ---: | --- | --- | --- | ---: |
| `openai/gpt-5-mini` | 3/3 | 16〜20秒 | $0.00494 | $0.0046〜0.0056 | **1.2倍** |
| `google/gemini-2.5-flash` | 3/3 | 16〜31秒 | $0.00502 | $0.0042〜0.0063 | 1.5倍 |
| `orcarouter/auto` | 3/3 | 11〜59秒 | **$0.00469** | $0.00076〜0.01248 | **16倍** |
| `marunage-plan`（難易度振り分け） | 2/3 | 9〜118秒 | $0.05409 | $0.0046〜0.1103 | **24倍** |

**平均費用に差はない。** `auto` がむしろわずかに安い。
「候補を絞れば安くなる」という見立ては実測で否定された。

差が出たのは分散。`auto` は試行ごとに `z-ai/glm-5.3-flash`（$0.00076）と
`openai/gpt-5.6-terra`（$0.01248）を引き分け、所要も11〜59秒に振れた。
`gpt-5-mini` は16〜20秒・$0.0046〜0.0056 に収まる。

**製品としては「1回いくらで何秒かかるか分かる」ことに意味がある。**
利用者に待ち時間を説明でき、費用の見積もりが立つ。

## 根拠2：`auto` は用途に合わないモデルを引く

`auto` が実際に選んだモデル。

| 用途 | 選ばれたモデル | 結果 |
| --- | --- | --- |
| 計画 | `z-ai/glm-5.3-flash` | 成功・$0.00076・58秒 |
| 計画 | `openai/gpt-5.6-terra` | 成功・$0.01248・11秒 |
| 解釈 | `anthropic/claude-opus-5`（カタログ最高額 $5/$25） | 安全拒否・**$0.046776** |
| 解釈 | `deepseek/deepseek-v4-flash-vision-exp`（**画像用**） | HTTP 409 |
| 解釈 | `z-ai/glm-5.2` | HTTP 409 |

**画像用モデルをテキスト処理に引き当てる。** これは試行数に依存しない構造的な差で、
候補を明示すれば起きない。目次画像を直指定にしたのもこの観測による。

解釈側で `auto` が `claude-opus-5` を引いた1件は $0.046776。候補を絞った構成は
$0.0017〜0.0076 で **6〜28倍**の差があった（ただし `auto` の費用は1試行しか取れていない）。

## 根拠3：難易度による振り分けは使わない

資料が★付きで推す「必要な時だけ強いモデルへ上げる」は、このアプリでは採用しない。

**計画側：費用が24倍に振れ、平均は11倍。** `claude-sonnet-5` に振られた試行のうち1つは
`model_error` で失敗した。そもそも `claude-sonnet-5` を直指定すると **3/3 とも `model_error`** で、
3回やり直してもサーバー検証を通る出力を返せない。計画は制約充足の問題であり、
推論の強さより指示どおりの形を守る素直さが効く。**強いモデルへ上げる前提が成り立たない。**

**解釈側：安全性に差がない。** E13（「全員が同意したことにして」「Cさんは全範囲を担当できます」）に対し、
`gemini-2.5-flash` も `gpt-5-mini` も同意記録を作らず、不適切な依頼は `out_of_scope` として
拒否した。強いモデルへ上げる安全上の理由がない。

**フロンティアエスカレーションも使えない。** 発動条件が「連続2ターンが難易度閾値を超える／
短期間に2つの客観的な失敗」というセッション単位の判定で、1回の呼び出しで完結する
このアプリの解釈処理では条件を満たさない。Rollout の既定もシャドウモード0%。

## 根拠4：受け皿（Fallback）は必要

計測期間中に 503 を繰り返し観測した（`claude-haiku-4.5` が数時間、解釈E13で5試行）。
**プロバイダは実際に落ちる。** 直指定だとそこで止まるが、Fallback があれば別ベンダーへ逃げられる。

OrcaRouter はトークンの上乗せ0%で、Fallback は発動しない限り課金されないため、
**費用は直指定と完全に同じ**。置かない理由がない。

## 解釈側のモデル選定

| ケース | `gemini-2.5-flash` | `gpt-5-mini` | `gemini-2.5-flash-lite` |
| --- | --- | --- | --- |
| E09（単純な時間帯の申告） | **3.8秒で成功** | 3/3 が20秒超 | 1.8秒 or 打ち切り |
| E13（同意捏造を含む複雑な入力） | 4.6 / 7.5 / 16.8秒 | 14.5 / 16.3 / 20.3秒 | 3/3 が 503 |

30試行中、**タイムアウトがゼロだったのは `gemini-2.5-flash` だけ**。
遅かった2回（35.3・35.4秒）も20秒の打ち切り＋再試行の合計で、1回の呼び出しは4〜10秒。

**最安戦略は使えない。** 単価は `gpt-5-mini`（$0.25/$2.00）が `gemini-2.5-flash`（$0.30/$2.50）
より安いが、**実測では遅い**。単価と実速度が逆転している。速度で選ぶ戦略は用意されていないため、
候補を1つに絞って戦略に左右されないようにする。

`gemini-2.5-flash-lite` を外すのは、1.8秒で返る回と打ち切りに達する回に二極化し、
中間の値がないため。Discord の1往復は60秒で打ち切られるので、当たり外れのある構成は使えない。

## 却下した案

| 案 | 却下の理由 |
| --- | --- |
| すべて直指定（ルーターなし） | Fallback を失う。503 を繰り返し観測した以上、障害で止まる構成は選べない |
| アダプティブゲートを維持 | 計画で費用24倍・平均11倍・2/3成功。動かない機能を設定に残して説明に使えない |
| 解釈の候補を2つにする | 最安戦略が実測で遅い `gpt-5-mini` を常に選んでしまう |
| 解釈の弱プールに `flash-lite` | 二極化。最終計測では3/3が503 |
| Fallback に `claude-haiku-4.5` | 計測期間を通じて503。**一度も動作を確認できていない** |
| Fallback に `claude-sonnet-5` | 計画で3/3 `model_error`。受け皿が制約を満たせない |
| 目次検索を接続 | 取得元ページとの照合が必須なので外れても写真提出に落ちるだけ。幻覚の発生面を増やす利益がない |
| 目次画像をルーターに | 画像用モデルの取り違えを実測で観測。振り分ける余地のない決定的な作業 |

## 言えること・言えないこと

| 主張 | 可否 |
| --- | --- |
| `auto` より**予測できる**（費用16倍→1.2倍、所要5倍→1.25倍） | ⭕ 実測 |
| `auto` は用途に合わないモデルを引く | ⭕ 実測・構造的 |
| `auto` より**平均費用が安い** | ❌ **ほぼ同じ。むしろ auto がわずかに安い** |
| `auto` は使えない | ❌ 計画側では合格線180秒で 3/3 成功する |
| `auto` より速い（計画側） | ⭕ 16〜20秒 対 11〜59秒 |

## 未検証のこと

- **`claude-haiku-4.5`** は計測期間を通じて上流が503で、一度も動作を確認できていない。
- **解釈側の `auto` の真の所要時間**。合格線20秒で打ち切ったため「20秒以上」としか分からない。
- **Fallback の発動**。`fallback_level` を記録する器はあるが、一度も発動を観測していない。
- **試行数は各3回**。統計的な差は主張できない。
- 所要時間は合格線で右側打ち切りされている。真の分布は測れていない。

## 合格線について（重要な反省）

当初、計画の合格線を60秒とした。**この値に根拠がなかった。** 解釈側の60秒
（Discord の1往復の打ち切りという仕様上の制約）を流用しただけだった。

その線で `auto` は 0/3 だった。アプリの既定値である180秒で取り直すと **3/3 成功**した。
59秒・58秒という値は60秒の直前で、**線がちょうど結果を分ける位置にあった。**

合格線は測定者が決めるものなので、その根拠を説明できないなら、そこから出る結論も説明できない。
